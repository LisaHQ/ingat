# ADR-0024 Adoption of a foreign deployment by payload import and restore, never in place

**Status:** Accepted (owner requirement, 2026-10-14; design revised after review the same day). Planned M4 slice 11.

## Context

The owner requires that Ingat can take over an app deployment it did not create (started by hand, from Container Manager or by another tool), next to backup, verify, restore, migration on update, rollback, purge and disaster recovery. No deployment awaits adoption yet; the requirement covers apps deployed outside Ingat later. Ingat proves ownership only by its own labels ([ARCHITECTURE.md](../ARCHITECTURE.md) §7.5), and Docker cannot add or change labels on an existing container, volume or network, so a foreign object can never become owned. Both v1 consumers back up and restore through their own commands; restore into a never-deployed instance exists from M2, and `import` arrives in M4 slice 10.

## Decision

Adoption is a payload import followed by the existing restore ([LIFECYCLE.md](../LIFECYCLE.md) §4.16). The owner quiesces the foreign project with its own tooling (restart policies cleared, writers stopped) and produces a payload with the app's own backup command. `ingat import --payload <dir> --into <i> --release <ref> --from <name> --reason TEXT` (class B) wraps it into a bundle of a new, `registered` instance with `consistency = "external"`, `origin = {adopted_from: <name>}` and the prepared candidate of `<ref>` as its recorded deployment, seals it, catalogues it as `imported` and verifies it; a drill must pass before `restore` accepts it; the restore into the never-deployed instance (class C) is the cut-over. Ingat never stops, starts, execs into, mounts, relabels, restores into or deletes a foreign object.

## Alternatives

Capture and restore driven by Ingat (the first design, rejected after review on 2026-10-14): a `FreezeForeign` step that stopped foreign containers by recorded ID, an `inventory` command, a capture project `<i>--a<seq>` with a policy exception for foreign binds, foreign secret sources and an external foreign network, a foreign fingerprint, a spike and two attention codes, about 500 runtime lines for a feature with no adoptee today. It also let the app's backup bookkeeping write into foreign data (the SQLite consumer records its backups in its own database), and a `docker stop` holds only until the daemon restarts: a foreign container with restart policy `always` comes back after the next reboot (live restore is off in Container Manager 24.0.2-1706), and one with `AutoRemove` is deleted by the stop. Relabel or recreate the foreign containers on their volumes (rejected: Docker cannot relabel a volume, and an unproved object would become deletable: safety floor F8, [LIFECYCLE.md](../LIFECYCLE.md) §1). Mount the foreign volumes as the new instance's live stores (rejected: no generation, no pre-change bundle, no ownership proof for a later prune or purge). A generic file copy by default (rejected: engine knowledge and no app-level consistency; deferred as `cold`, [ADR-0010](0010-one-data-strategy-app-native-tasks.md)).

## Consequences

About 150 runtime lines in M4 (the payload form of `import`, the bundle fields, `adopted_from`), on the import and restore machinery; no new step type, side project, policy exception or attention code, and additive record fields only (`adopted_from`, a bundle's `origin`, the `external` consistency value: [ADR-0023](0023-record-compatibility-within-state-schema.md)). The quiesce and export are manual owner steps in the operator guide; the payload's consistency is the owner's statement, and the drill plus the app's own restore checks are the evidence. Operations agents never run those steps (`docker` is in their deny rules: owner decision OD-10). Adoption costs downtime from the writer stop to the cut-over; the owner repoints the reverse proxy at cut-over. An app without a backup command the owner can run against the foreign deployment waits for the `cold` strategy. [ADR-0001](0001-separate-repository-rebuilt-from-scratch.md) is unaffected: adoption reads only the payload, never the predecessor's labels, records or bundles.
