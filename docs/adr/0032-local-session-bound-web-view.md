# ADR-0032 Local session-bound web view (`ingat ui`)

**Status:** Accepted (owner, 2026-10-19). Changes the non-goal "a web UI" in [ARCHITECTURE.md](../ARCHITECTURE.md) §1.4 and the "Never: web UI" row of [ROADMAP.md](../ROADMAP.md) §4 to "a web service on the host", and narrows the no-listener sentences of ARCHITECTURE §3.3 and §9.3 to one named exception. Supersedes in part [ADR-0022](0022-delegated-concerns.md): its no-listener consequence restates the §1.4 non-goal this ADR narrows, and is narrowed with it. [ADR-0013](0013-approval-classes-and-plan-files.md) (approval classes) and [ADR-0019](0019-secrets.md) (secrets) apply unchanged.

**In plain words:** `ingat ui` will open a read-only web page for your session, reachable only from the machine itself (or through an SSH tunnel) with a secret link printed in your terminal, with plain explanations and a helper that writes commands for you to run. It cannot change anything, and its first version has no access to Docker. Planned.

## Context

M1 runs end to end on a scratch daemon (not yet in CI or on a host), but every state, pause and recovery is explained only in the design documents. The first real users are newcomers who reach for an automatic tool precisely because they are not experts, and the owner requires every user-facing word to be everyday language (applied to the CLI on 2026-10-19). The CLI prints stable `code` strings and `next` commands, which is the right machine contract but not a picture a newcomer can read. The non-goal list forbade a web UI, a daemon and an agent because each adds a listener, a second enforcement point or a long-running root process; ARCHITECTURE §3.3 and §9.3 say the Docker socket is mounted only into ephemeral containers with no listener.

Three designs were judged: this read-only view, a loopback console container that drives the CLI with buttons for class B and C, and a hosted control plane with an outbound agent. The owner chose "local first, cloud later": the local view now, a controlled action path as a later ADR, and the cloud as the hosted service of [ADR-0033](0033-commercial-boundary-report-and-hosted-service.md). A review of the first draft found that a listener that lives up to 12 hours must not sit in a container that holds the Docker socket; the first version therefore runs without it.

## Decision

Replace the non-goal "web UI" by "web **service** on the host" and allow exactly one form: **a loopback-only, session-bound, read-only web view started by a foreground CLI command, in a CLI container that has no Docker socket, with no write endpoint.** A daemon, an agent, a plugin system, host hooks, TLS, a non-loopback bind, accounts, a run or approve button, and any mutation from the browser stay forbidden.

**Command.** `ingat ui [--port N] [--idle MIN]`: a new `COMMANDS` row `Cmd("A", "", "none", False, True)` (read-only, no lock, no approval, not unattended, foreground). Gate tier 0, so it works on an uncertified host. It prints one line with `http://127.0.0.1:7117/s/<token>/`, the `ssh -L 7117:127.0.0.1:7117 <user>@<host>` forward line and "Ctrl-C ends it", then serves until Ctrl-C, SIGTERM, `--idle` minutes without a request (default 30) or a hard cap of 12 hours. A busy port refuses with exit 2, code `ui-running`.

**Where it runs, and without the socket.** The wrapper's one template gains a second `exec` branch: when the first argument is `ui`, the `docker run` line omits `-v /var/run/docker.sock:/var/run/docker.sock`; everything else (the roots, the probe volume read-only, the release files, `--network host`, `--log-driver none`, `role=cli`) is the same. The view therefore serves only what is on disk under `INGAT_ROOT`: `host.json`, certifications and `host/attention.json` (the attention set `scheduled status` writes hourly), every instance's records, deployments, catalog and verification records, and every operation's `plan.json`, `steps.jsonl`, `progress.log`, `result.json` and run file. Live container state, `ps`, `logs`, the probe-backed parts of `status` and `doctor`, and orphan evidence need the socket and arrive with the second version. The bind address is the constant `127.0.0.1`; no flag changes it. Requests whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>` get 421, so a reverse proxy cannot expose it.

**Auth.** One `secrets.token_urlsafe(24)` per session, printed only to the terminal and never written to disk. `GET /s/<token>/` sets `ingat_ui=<token>; HttpOnly; SameSite=Strict; Path=/` and redirects to `/`. Every `/api/*` and `/events/*` request needs the cookie (`hmac.compare_digest`) and `Sec-Fetch-Site: same-origin|none`. A wrong token answers 404 for the whole tree after a one-second delay. Every answer carries `Content-Security-Policy: default-src 'self'; connect-src 'self'; frame-ancestors 'none'`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff` and `Cache-Control: no-store`. No external asset, no inline script.

**Modules** (each at or under 600 lines; `cli → ops` is the allowed direction): `cli/commands_ui.py` (the `ui` parser, help and handler, registered from `parser()` so `cli/commands.py` does not grow); `cli/ui_server.py` (server, token, cookie, Host and Sec-Fetch checks, headers, static files from package data, routes, a server-sent-events tail of `progress.log` and `steps.jsonl`, idle timer, SIGTERM); `cli/ui_api.py` (GET-only handlers that render the records above as the same Report shapes `--json` prints, through the existing read-only functions of `ops/status.py` that take no daemon); `cli/ui_compose.py` (per command a schema: fields, validation rules from `model/instance.py`, class from `COMMANDS`, two plain sentences, what it writes, which floor protects it; a renderer of the exact argv line; the offline install block for the generic Linux and DSM profiles); the plain-word tables of `model/words.py`, extended so that every `code`, attention code, operation state and exit code has an entry (a test asserts it); `cli/ui_static/` (vanilla HTML, CSS and JavaScript, package data, no build step). Before U1, `doctor` and its helpers move from `ops/status.py` (595 lines) into a new `ops/doctor.py`, which then gains `ui-stale`.

**Views.** A host-setup checklist with ticks taken from the records (bind engine, record facts, certify) until the host is certified; Host; Instances; one instance with Status (records plus the hourly attention set, dated), History and Tasks; Backups and test restores; Plans (M2); Recover. An attention panel sits at the top of every page whenever the attention set or a record calls for it, showing the one `next` the CLI printed as a copy card. An expired plan, or one whose fingerprint no longer matches, says so in plain words and renders the `ingat plan …` line again. Every page states when its data was written and names `ingat status` as the way to refresh live state.

**Path deny list (by construction).** Nothing under `instances/*/secrets/`, `instances/*/env/`, `keys/`, `inbox/`, `ops/*/secrets/`, `ops/*/env/`, `cache/`; `instance.toml` is never served raw. No handler calls a mutating adapter method, and the `ui` modules never import `core/executor`, `core/opening` or the Docker and Compose adapters (enforced by the import test).

**Visibility and packaging.** `doctor` flags a `role=cli` container running longer than 12 hours (`ui-stale`) and lists a running view (port, age). Every `--json` Report gains `output_schema: 1` (the shape of the CLI's own answers; unrelated to the outbound report payload of ADR-0033); the view renders unknown fields raw instead of failing. Same image and `pyproject.toml`; standard library only; one wrapper template with the `ui` branch, written by `install.sh`. `image/build.sh` concatenates the same bundle into the release asset `getting-started.html` (offline: Start and Composer views only), listed in `SHA256SUMS`.

**Owner decisions recorded (2026-10-19).** Accept this ADR. Default port 7117 with `--port`, no address flag. The first version writes nothing (the owner runs `ingat plan …` on the terminal). Delivery: the whole first version after the M2 plan hand-over slice. Idle 30 minutes, cap 12 hours. `getting-started.html` is a release asset only. The view is English in its first version; the word table allows a Vietnamese set later without logic changes. The first version runs without the Docker socket (the first proposal deferred this; the review changed it, and the owner confirmed it on 2026-10-20); the live Docker data moves to the second version.

## Alternatives

1. **A loopback console container** that spawns the CLI and offers buttons for class B and C: the best newcomer usability, but a long-running root-equivalent listener with a class-C-capable session, a configuration path to reverse-proxy exposure, a second argv builder that drifts from the wrapper, and a dependency on the M2 generalisation of `plan`/`apply`. Rejected as the first form; its checklist, headers, stale-plan handling and socket test are adopted here, and its action path is the named second version.
2. **A hosted control plane with an outbound agent**: the page that handles the approval passphrase is served by the control plane, so a compromised cloud could approve class C; three non-goals and §9.3 would change at once; a socket-holding agent on every host; the largest effort and a permanent operating burden. Rejected as the newcomer view; the cloud is the hosted service of ADR-0033 and never holds approval.
3. **The same view inside the socket-holding CLI container** (the first draft): rejected, because any flaw in a hand-written HTTP layer would then be a browser path to a root process that holds the Docker socket; the records on disk give the newcomer most of the picture without that exposure.
4. **No view, better docs only**: does not meet the owner's goal.

## Consequences

- Newcomers see every recorded state and the one next command in plain words; every change is still a paste into SSH, approved there; live container state needs `ingat status` until the second version.
- Plain-language copy lives in one word table for the CLI, the docs and the view.
- **Second version, by its own ADR after the first has run on a real host:** a controlled spawn path through which the view runs `status`, `doctor`, `ps` and `logs` in an ordinary CLI container and stages `plan …` (class A, writes only `plans/`) and `apply <hash>` with a typed instance name; never class D, `secret set` or terminal tasks; the first version's zero-write and no-socket tests become the regression guards the second must deliberately loosen; any spawner takes the `docker run` argv from the wrapper's environment, never rebuilt in code. Also second version: `ingat manifest <repo-url> <ref> --json` (class B, writes only `cache/git/`) so the new-instance form is generated from the declared params, keys, secrets and stores.
- Suites: no-trace (a full view session over every page leaves `instances/` and the labelled inventory identical), no-socket (the `ui` container has no socket mount; `ss -ltn` in the host namespace shows only `127.0.0.1:<port>`), crash matrix (the Recover card equals the `next` the last result recorded, for every terminal state), session loss (SIGTERM to `ui` leaves no container and no file), secret canary (every response, event line and static file), upgrade suite for `output_schema`. Both pinned dind tags and the arm64 lane run them.
- Residual risk: a browser-side flaw can read redacted records on disk; there is no path from the view to Docker. Real-browser behaviour is checked by hand on a certified host; CI covers the HTTP layer and the rendered text.
- Design documents changed with this ADR: ARCHITECTURE §1.4, §3.3 and §9.3 (the narrowed wording with a Planned note), LIFECYCLE §2 (the `ui` row), README (the feature row). `ARCHITECTURE.md` §4.1 and §5.1 and the README command table gain their rows when the slice lands ([ROADMAP.md](../ROADMAP.md) §5).
