# ADR-0014 Version gate in tiers, generated from CI, without override

**English** · [Tiếng Việt](0014-tiered-version-gate.vi.md)

**Status:** Accepted; revised 2026-10-14, before any implementation, for platform-neutral host support ([ADR-0025](0025-host-baseline.md)): the host certification is required on every host, not only on vendor builds, and is matched on the Engine build that `docker version` reports, not on the Engine package build.

**In plain words:** Which commands may run depends on the machine. Read-only commands run anywhere. Backups that leave the app running, and their checks, also run on an untested Docker of version 24.0 or later, with a recorded warning. Everything else runs only on a Docker line that CI tested, and only after the machine's exact system and Docker build passed `selftest --host`. There is no override.

## Context

The predecessor tested Engine 28.5.1 / Compose 2.40.3 while the first platform runs Engine 24.0.2 with an unknown Compose. A platform update (for example a Container Manager update on DSM, or an Engine package update on a Linux host) could silently stop nightly backups if the gate were all-or-nothing (Lens B must-fix). An override for every mutation is unsafe (Lens A must-fix). Hosts range from Linux servers with upstream Engine to appliances with vendor-built engines.

## Decision

Gate tier 0 read-only on any engine; gate tier 1 (online backup and verify) on an untested engine with API ≥ 1.43, with a recorded warning; gate tier 2 (everything else, drills included) only for combinations in `tested.json` (Engine major.minor × architecture), generated by CI, and only with a host certification of the host's platform build: the OS or appliance release (update level included), the Engine build as `docker version` reports it (Engine version, Git commit and build time, containerd and runc versions), kernel, storage driver and architecture, as detected facts, embedded in the release or produced locally by `selftest --host`. The Engine package build (on DSM the Container Manager build) is recorded by `facts.sh` in the committed file, not matched by the gate, because the tool container cannot see it. The rule is the same on every host. No override flag or file ([ARCHITECTURE.md](../ARCHITECTURE.md) §3.6). The gate tiers are distinct from the support tiers of [ADR-0025](0025-host-baseline.md).

## Alternatives

Owner override file (rejected). Refuse backups on an untested engine (rejected). Treat upstream `docker:24.0.2-dind` as evidence for a vendor-built Engine (rejected: on DSM 7.4.1 with Container Manager 24.0.2-1706, Synology's build runs on a vendor kernel, 4.4.x on many DSM 7.x platforms, with a storage driver that follows the volume filesystem (aufs on ext4 volumes, btrfs on Btrfs volumes), cgroup v1 and no CPU CFS quota: [ADR-0025](0025-host-baseline.md)). Require a certification only on vendor builds (rejected: no detected fact that separates a vendor build from an upstream one is verified yet, and one uniform rule is simpler; a candidate, the Engine Git commit compared with the upstream commit each CI lane records, is Unverified for vendor builds, and adopting it would be a new ADR).

## Consequences

A new Engine line or architecture needs a tool release; nightly backups continue across a platform update; any platform update (an OS or appliance update level, an Engine update that changes what `docker version` reports, such as a Container Manager update that changes the Engine, a new kernel or storage driver; on a Linux host every kernel update, once the host has rebooted into it) needs a fresh `selftest --host` before gate tier 2 runs again, and until then scheduled drills, which are gate tier 2, refuse with exit 2 and `status` shows `uncertified` attention. On a support-tier-2 platform, the full certification checklist and a newly committed host file are needed only for a new platform release line or a vendor package build that changes the Engine, containerd or runc (on DSM: a new DSM minor line or such a Container Manager build). A tool release needs no host certification of its own; the host upgrade runs `selftest --host` with the new version before it replaces the wrapper ([ARCHITECTURE.md](../ARCHITECTURE.md) §3.5, §10.4).
